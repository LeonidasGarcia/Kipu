# Data Model: EP-APS - Acceso, Perfil y Seguridad

## Ownership Rules

- `user_id` siempre representa `auth.users.id`; nunca se obtiene de un campo editable del usuario.
- Una consulta Room privada recibe el propietario activo de `SessionCoordinator`; no existe un DAO de lectura global para UI.
- Las operaciones pendientes conservan su `user_id` original y solo se envían cuando coincide con la sesión remota válida.
- Biometría, permisos y cooldown son locales al dispositivo; perfil y preferencias se sincronizan.

## Remote Entities

### Account Identity (`auth.users`, provider-owned)

| Field | Type | Rules |
|-------|------|-------|
| `id` | UUID | Stable account owner; generated by Auth. |
| `email` | provider field | Normalized by provider; never used as database ownership key. |
| `email_confirmed_at` | timestamp nullable | A null value means pending verification when confirmation is required. |

Credentials, recovery secrets and sessions remain provider-owned and are not copied into application tables.

### Profile (`public.profiles`)

| Field | Type | Rules |
|-------|------|-------|
| `user_id` | UUID PK/FK | References `auth.users(id)` with cascade delete. |
| `display_name` | text | Presentation only; not an authorization claim. |
| `currency_code` | char(3) | ISO-style uppercase code; default `PEN`. |
| `time_zone` | text | Valid IANA identifier when present. |
| `month_start` | smallint | 1 through 28 to remain valid every month. |
| `hide_balances` | boolean | Visual privacy only. |
| `theme_mode` | text | `SYSTEM`, `LIGHT`, or `DARK`. |
| `revision` | bigint | Starts at 1; increments atomically on preference update. |
| `created_at` | timestamptz | Server generated. |
| `updated_at` | timestamptz | Server generated on accepted write. |
| `preferences` | jsonb | Reserved extension bag; no authorization or biometric state. |
| `biometric_enabled` | boolean legacy | Forced false and deprecated; omitted from all app contracts. |

**Indexes and authorization**: the PK indexes `user_id`; RLS is enabled and forced. `authenticated` can SELECT only its row. `profile_preferences_executor` can SELECT/UPDATE only the row where `(select auth.uid()) = user_id`. `profile_bootstrap_executor` can INSERT and can SELECT only the current `auth.uid()` row for `ensure_profile()`; it is reachable only through the Auth trigger or repair RPC. Writes go through the revision-aware RPC. `anon` has no table DML.

### Profile Role and Policy Matrix

| Principal | Table privileges | Function privileges | RLS predicate / restriction |
|-----------|------------------|---------------------|-----------------------------|
| `anon` | None on profiles/receipts | None on profile functions | No policy. |
| `authenticated` | SELECT on `profiles` only | EXECUTE `update_profile_preferences` and `ensure_profile` | SELECT where `(select auth.uid()) = user_id`. |
| `profile_preferences_executor` | SELECT/UPDATE `profiles`; SELECT/INSERT `profile_preference_receipts` | Owns update RPC; no login/inheritance to clients | Policies on both tables require non-null `(select auth.uid()) = user_id`. |
| `profile_bootstrap_executor` | INSERT plus owner-scoped SELECT on `profiles` | Owns trigger/ensure functions; no login/inheritance to clients | INSERT policy permits the role; SELECT policy requires non-null `(select auth.uid()) = user_id`; functions accept no target user argument and derive identity only from `NEW.id` or `auth.uid()`. |
| `PUBLIC` | None | EXECUTE explicitly revoked from all profile functions | No policy. |

All three functions are `SECURITY DEFINER SET search_path = ''` with fully qualified objects. `update_profile_preferences` accepts no `user_id`; it locks and mutates only the row for `auth.uid()`. `ensure_profile` accepts no arguments, requires non-null `auth.uid()`, performs `INSERT ... ON CONFLICT DO NOTHING`, then selects only that owner row. The Auth trigger function uses `NEW.id` and is not directly executable by `anon` or `authenticated`.

### Registration Rate Bucket (`private.registration_rate_buckets`)

| Field | Type | Rules |
|-------|------|-------|
| `bucket_hash` | bytea PK | HMAC of category plus normalized origin; no raw IP/email. |
| `window_started_at` | timestamptz | Server time. |
| `attempt_count` | integer | Non-negative. |
| `blocked_until` | timestamptz nullable | Finite only; no permanent lock. |
| `updated_at` | timestamptz | Server time; supports retention cleanup. |

Only a narrowly granted server function can consume a bucket. No Data API role can read this table. Rows older than the approved retention window are deleted by scheduled maintenance.

### Profile Preference Receipt (`private.profile_preference_receipts`)

| Field | Type | Rules |
|-------|------|-------|
| `user_id` | UUID | Authenticated owner; part of primary key. |
| `operation_id` | UUID | Stable client operation; part of primary key. |
| `payload_hash` | bytea | SHA-256 over canonical contract version, expected revision and delta. |
| `result` | jsonb | First non-secret RPC result returned for duplicate replay. |
| `resulting_revision` | bigint | Revision after accepted write, or current revision for conflict. |
| `created_at` | timestamptz | Server time for retention/audit. |

The primary key is `(user_id, operation_id)`. Repeating the same ID/hash returns `DUPLICATE` plus the stored original status/snapshot without another update. Repeating an ID with another hash returns an operation collision and changes nothing. Conflict results are returned as committed data, not raised exceptions, so their receipts survive. The table is not Data API-readable. A dedicated `NOLOGIN`, non-superuser, non-`BYPASSRLS` function owner has only the required privileges; `PUBLIC` and client roles have no table access.

| Field | Type | Rules |
|-------|------|-------|

| `currency_code` | String | Three uppercase letters. |

| `updated_locally_at` | Instant | Device timestamp for UI, not conflict authority. |

### ProfilePreferenceOutbox (`profile_preference_outbox`)

| Field | Type | Rules |
|-------|------|-------|
| `operation_id` | UUID PK | Stable across retries. |
| `user_id` | UUID indexed | Must match active remote session before send. |
| `expected_revision` | Long | Revision read before local edit. |
| `payload` | serialized preference delta | Contains only changed profile fields. |
| `status` | enum | `PENDING`, `IN_FLIGHT`, `WAITING_FOR_AUTH`, `CONFLICT`, `COMPLETED`, `TERMINAL_ERROR`. |
| `attempt_count` | Int | Retry accounting. |
| `next_attempt_at` | Instant nullable | Bounded exponential retry. |
| `created_at` | Instant | Audit/order metadata. |
| `updated_at` | Instant | State transition metadata. |

Unique constraint: `(user_id, operation_id)`. A payload conflict for the same operation ID is a terminal local integrity error.

### DeviceAccountSettings (`device_account_settings`)

| Field | Type | Rules |
|-------|------|-------|
| `user_id` | UUID PK | Local account partition. |
| `local_unlock_enabled` | Boolean | Default false; set true only after successful prompt. |
| `unlock_authenticators` | bit mask | Approved Android authenticators, no biometric material. |

This row never synchronizes and is excluded from Android backup/device transfer with `kipu.db`.

### InstallationPermissionState (`installation_permission_state`)

| Field | Type | Rules |
|-------|------|-------|
| `source` | enum PK | `OWN_NOTIFICATIONS` or `OTHER_APP_NOTIFICATION_CONTENT`. |
| `device_authorization` | enum | `NOT_APPLICABLE`, `NOT_REQUESTED`, `GRANTED`, `DENIED`, `REVOKED`, `UNAVAILABLE`. |
| `last_checked_at` | Instant | Re-read on foreground and before source actions. |

This models Android's application/installation-wide state. It is not duplicated as if the OS grant changed when the active account changes.

### AccountSourceConsent (`account_source_consent`)

| Field | Type | Rules |
|-------|------|-------|
| `user_id` | UUID | Account/device partition; part of primary key. |
| `source` | enum | Part of primary key. |
| `consent_state` | enum | `NOT_EXPLAINED`, `EXPLAINED`, `GRANTED`, `DENIED`, `REVOKED`. |
| `capability_state` | enum | `UNKNOWN`, `ALLOWED`, `DENIED`; conservative default is denied. |
| `explanation_version` | Int | Re-explain when consent text materially changes. |
| `updated_at` | Instant | Local observation time. |

This row is local to an account on the installation and never grants an Android permission by itself.

## Non-Room Security State

### Local Owner Marker

Stored in the encrypted session boundary, not as an authorization token.

| Field | Meaning |
|-------|---------|
| `verified_user_id` | Last account verified on this installation and still locally active. |
| `explicitly_signed_out` | Prevents offline reopening after explicit logout. |
| `verified_at` | Diagnostic policy timestamp; no remote authorization. |

### Local Lock

In-memory process state with no secret payload.

| Field | Meaning |
|-------|---------|
| `state` | `DISABLED`, `LOCKED`, `UNLOCKING`, `UNLOCKED`. |
| `background_started_elapsed_ms` | Monotonic timestamp. |
| `lock_reason` | `APP_START`, `BACKGROUND_TIMEOUT`, `OWNER_CHANGED`, `AUTHENTICATOR_CHANGED`. |

Process death always restarts as `LOCKED` when local unlock is enabled.

### Auth Cooldown

Non-secret per-installation counters persist outside Room but are excluded from backup. Keys use a keyed hash of normalized identifier plus operation; no password is retained.

```text
     ├── (1) user_profiles [local cache]
     ├── (0..*) profile_preference_outbox

     ├── (0..*) account_source_consent

```

## State Transitions

### Session Exposure

```text
NoOwner --successful remote auth--> ActiveOwnerLocked/ActiveOwnerOpen
ActiveOwnerOpen --remote expiry offline--> LocalOnlyOpen
LocalOnlyOpen --refresh succeeds same user--> ActiveOwnerOpen
AnyActive --explicit logout--> NoOwner
AnyActive --different successful user--> NoOwner --> NewActiveOwner
```

The private navigation graph is available only when an owner is active. `LocalLock=LOCKED` replaces private content with an opaque gate.

### Profile Synchronization

```text
SYNCED --local valid edit--> PENDING
PENDING --matching auth + accepted revision--> SYNCED(revision + 1)
PENDING --duplicate operation/hash--> prior result, no second write
PENDING --no valid remote session--> WAITING_FOR_AUTH
PENDING --revision mismatch--> CONFLICT
PENDING --operation ID with different hash--> TERMINAL_ERROR
CONFLICT --user/repository resolves against fresh revision--> PENDING
```

The RPC serializes concurrent updates by locking the owner's profile row. It checks an existing receipt before mutation, computes a canonical payload hash including contract version and expected revision, and writes the result receipt in the same transaction as an accepted update. Empty deltas return `INVALID_INPUT` and create no receipt.

### Local Protection

```text
DISABLED --successful activation prompt--> UNLOCKED(enabled)
UNLOCKED --app start/process death--> LOCKED
UNLOCKED --background >= 60s--> LOCKED
LOCKED --successful system prompt--> UNLOCKED
LOCKED --cancel/failure--> LOCKED
UNLOCKED --disable after confirmation--> DISABLED
```

### Installation Permission State

```text
NOT_REQUESTED --platform grants--> GRANTED
NOT_REQUESTED --platform rejects--> DENIED
GRANTED --external/in-app revoke observed--> REVOKED
DENIED/REVOKED --platform grants later--> GRANTED
```

### Account Consent State

```text
NOT_EXPLAINED --show rationale--> EXPLAINED
EXPLAINED --account continues to request--> GRANTED
EXPLAINED --account declines--> DENIED
GRANTED --account revokes consent--> REVOKED
DENIED/REVOKED --show updated rationale--> EXPLAINED
```

External Android revocation changes only `installation_permission_state`; it does not erase the account's prior consent record. Processing requires current platform grant, current account consent and capability independently. In HU-05, notification-content capability is always denied/unavailable, so no signal is processed.

## Validation and Migration Rules

- Normalize email for comparison but let Supabase Auth own canonical identity behavior.
- Reject `month_start` outside 1..28 and preserve the prior value.
- A currency change never updates transaction amount/currency columns.
- Room migration 1→2 creates all five new tables only and preserves all EP-PLA rows/outbox states. Migration tests verify restart persistence, installation permission shared across two accounts, and separate account consent rows.
- Remote migration first recreates the current `profiles` baseline if absent, backfills every existing `auth.users` row with `ON CONFLICT DO NOTHING`, then adds revision/constraints and hardening idempotently. Runtime `ensure_profile()` performs the same owner-derived upsert if a read finds no row.
- Remote receipt migration preserves idempotency across network loss and rejects operation-ID collisions before profile mutation.
- The inspected remote has 0 profiles and 0 `biometric_enabled=true` rows on 2026-09-20. Migration asserts no active legacy value and aborts for explicit remediation if that precondition changes; it never silently disables protection.
- Migration tests use representative profile rows and two Auth users before any remote application.
